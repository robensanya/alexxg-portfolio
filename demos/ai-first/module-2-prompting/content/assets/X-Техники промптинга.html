Zero-Shot Prompting
Базовый подход: даёшь модели задачу без примеров и объяснений — она выполняет её опираясь только на свои знания и твою инструкцию.
Когда использовать
→
Задача простая и однозначная
→
Нет готовых примеров под рукой
→
Нужен быстрый черновик или первый вариант
Пример
Промпт
«Напиши короткое письмо коллеге с просьбой перенести встречу на завтра на час позже. Тон — дружелюбный, до 5 предложений.»
💡Чем конкретнее цель, формат и ограничения — тем лучше сработает даже без примеров.
Few-Shot Prompting
Даёшь модели 1–3 примера идеального результата — и она подхватывает нужный стиль, формат или логику ответа.
Когда использовать
→
Нужен конкретный стиль или тон, который сложно описать словами
→
Модель даёт «не то» при обычном запросе
→
Есть образцы из реальной работы, которые можно показать
Пример
Инструкция
«Пиши заголовки для постов в нашем Telegram-канале. Вот примеры хороших заголовков:»
Примеры (few-shot)
— «Почему первые 10 минут встречи решают всё»
— «Три вопроса, которые стоит задать до старта проекта»
— «Как мы сократили онбординг с двух недель до трёх дней»
Задача
«Напиши 5 заголовков про использование AI в HR.»
💡Достаточно 1–3 примеров. Чем они точнее отражают желаемый результат — тем лучше модель его воспроизведёт.
Step-by-Step
Ты сам задаёшь модели последовательность шагов. Не «сделай это», а «сначала сделай А, потом Б, потом В».
Когда использовать
→
Важно, чтобы модель не пропустила ни одного этапа
→
Задача имеет чёткую логику выполнения, которую ты контролируешь
→
Хочешь управлять процессом, а не только результатом
Пример
Промпт
«Проанализируй отзыв клиента по шагам:
1. Определи основную проблему
2. Оцени эмоциональный тон (позитив / негатив / нейтрально)
3. Выдели конкретные пожелания клиента
4. Предложи формулировку ответа

Отзыв: [текст]»
💡Чем сложнее задача, тем полезнее задать шаги явно — модель меньше «фантазирует» и точнее следует нужной логике.
Chain-of-Thought
Модель сама рассуждает вслух перед тем, как дать финальный ответ. Ты не задаёшь шаги — она выстраивает их сама.
Чем отличается от Step-by-Step
↔
Step-by-Step — ты задаёшь шаги сам, модель следует им
↔
Chain-of-Thought — модель сама строит логику рассуждения до ответа
Когда использовать
→
Задачи, требующие логики, анализа или оценки
→
Когда важно понять ход рассуждений, а не только получить ответ
→
Хочешь проверить, не «угадывает» ли модель ответ
Пример
Без Chain-of-Thought
«Стоит ли нам запускать новый курс в сентябре?»
С Chain-of-Thought
«Стоит ли нам запускать новый курс в сентябре? Подумай вслух: рассмотри аргументы за и против, учти сезонность и типичную загрузку команды, и только потом дай рекомендацию.»
💡Фраза «подумай вслух» или «покажи ход рассуждений» — простой способ включить Chain-of-Thought в любой промпт.
Prompt Chaining — цепочка промптов
Сложная задача разбивается на несколько отдельных промптов. Результат одного становится входом для следующего.
Когда использовать
→
Задача слишком большая для одного промпта
→
Нужно контролировать качество на каждом этапе
→
Каждый шаг требует разной инструкции или роли
Пример: саммари встречи → письмо
1
Извлечь договорённости
«Из транскрипта выдели все договорённости и ответственных»
2
Структурировать
«На основе списка — сделай саммари по блокам: решения / задачи / вопросы»
3
Написать follow-up
«По саммари напиши письмо команде — коротко, с чёткими next steps»
💡Думай о цепочке как о конвейере: хороший результат на каждом шаге = качественный финал.
Tree of Thoughts — дерево мыслей
Модель рассматривает несколько возможных путей решения, сравнивает их и выбирает лучший. Не один ответ — а несколько гипотез.
Когда использовать
→
Несколько возможных путей решения, нужно выбрать лучший
→
Задача на стратегию, концепцию или оценку альтернатив
→
Первый вариант ответа часто бывает поверхностным
Пример
Обычный запрос
«Предложи стратегию продвижения нового курса.»
С Tree of Thoughts
«Предложи 3 разных стратегии продвижения нового курса: через экспертный контент, через партнёрства, через performance. Для каждой — логику, плюсы, риски. Затем сравни и выбери лучшую для запуска с ограниченным бюджетом.»
💡Чем больше возможных путей у задачи — тем ценнее этот подход. Если ответ очевидный — лучше обычная цепочка.
Температура (Temperature)
Параметр, который управляет тем, насколько «предсказуемой» или «творческой» будет модель. Чем выше — тем больше вариативности в ответах.
Как работает шкала
0.0–0.3
Точность — факты, расчёты, инструкции, код. Модель выбирает наиболее вероятный ответ.
0.4–0.7
Баланс — большинство рабочих задач: письма, саммари, анализ. Оптимальная зона для старта.
0.8–1.0
Творчество — брейнштормы, идеи, нестандартные решения. Ответы разнообразнее, но менее предсказуемы.
Где настраивается
→
В интерфейсах с расширенными настройками (ChatGPT API, Claude API, некоторые UI)
→
В обычном чате — через формулировку: «дай нестандартные идеи» или «ответь строго по фактам»
💡Нет «правильной» температуры — есть подходящая под задачу. Для точных ответов снижай, для идей — повышай.
